# Habit Tracker — ТЗ (Telegram Mini App)

Особистий трекер звичок: **тренування** + **англійська**. Мова інтерфейсу — українська.
Реалізація поетапно (див. «Етапи»). Цей файл — джерело правди для всіх сесій; якщо рішення змінюються — онови його.

---

## 1. Архітектура

| Частина | Що це | Де |
|---|---|---|
| Інтерфейс | Статичний сайт, чистий HTML/CSS/JS, **без збірки і без npm** (ES-модулі дозволені, кілька файлів ок) | GitHub Pages (корінь репо або `/docs`) |
| Вхід | Telegram-бот «Habit Tracker», відкриває Mini App (Menu Button / Main Mini App) | @BotFather |
| Дані | `Telegram.WebApp.CloudStorage` (синхронізація між iPhone і Telegram Desktop) | Хмара Telegram |
| Експорт файлів | Cloudflare Worker: приймає файл від Mini App, бот надсилає його користувачу в чат через `sendDocument` | `worker/` у репо, деплой вручну через дашборд Cloudflare |

- SDK: `https://telegram.org/js/telegram-web-app.js`.
- XLSX: SheetJS з cdnjs, **закріплена версія**.
- **Браузерний режим:** якщо відкрито поза Telegram — сховище `localStorage` + банер «Режим браузера, дані лише на цьому пристрої». Потрібно для тестування на Mac. Код доступу до даних — через один адаптер (`storage.js`) з двома реалізаціями.
- Нагадувань **немає** (користувач використовує Google Calendar). GitHub Actions не потрібні.

## 2. Безпека
- Токен бота **ніколи** не потрапляє в репо. Лише секрет `BOT_TOKEN` у Cloudflare Worker.
- Worker перевіряє `initData` від Telegram (HMAC-SHA256 за офіційною схемою валідації Mini Apps), бере `user.id` лише з перевіреного `initData`, відхиляє старі `auth_date` (> 24 год).
- CORS: дозволити лише origin GitHub Pages (змінна `ALLOWED_ORIGIN`).
- Ліміт розміру файлу експорту ~2 МБ.

## 3. Розклад (за замовчуванням, редагується в Налаштуваннях)

| День | Звичка | Деталі |
|---|---|---|
| Пн | Тренування | **День 1** — горизонтальні тяги та стабілізація тазу |
| Вт | Англійська | заняття |
| Ср | Тренування | **День 3** — функціональна стабілізація та комплексні тяги |
| Чт | Англійська | заняття |
| Пт | Тренування | **День 2** — вертикальні вектори та передня поверхня стегна |
| Сб, Нд | вихідні | — |

- **Бонусні дні:** можна відмітити звичку в день поза розкладом (напр. англійська в суботу) — зараховується як бонус, не впливає на % пропусків негативно.
- **Пауза:** періоди (хвороба, поїздка) з датою початку/кінця і міткою. Дні паузи не є пропусками і **не ламають серію**.
- Вихідні й дні без запланованої звички серію не ламають.

## 4. Модель даних (CloudStorage)

Ліміти CloudStorage: до 1024 ключів на користувача, значення до 4096 символів.

- Запис: ключ `e:YYYY-MM-DD:train` або `e:YYYY-MM-DD:eng` → JSON.
- Налаштування: `settings` (розклад, паузи, контрольні точки, `schemaVersion`).
- Досягнення: `ach` (id → дата отримання).
- Близько 5 записів на тиждень → запасу ключів на кілька років. Закласти функцію «упакувати старі місяці» (кілька записів в один ключ `m:YYYY-MM`), але запускати лише коли ключів > 900.
- Завжди валідувати довжину перед записом; при помилці CloudStorage — показати статус і повторити.
- Статус синхронізації в шапці: «збережено» / «зберігаю…» / «помилка».

### Тренування (`train`)
```json
{
  "s": "done | miss",
  "bonus": false,
  "dur": "lt60 | 60-70 | gt70 | null",
  "back": true | false | null,
  "energy": 1-5 | null,
  "reasons": ["tired","no_time","back","sick","other"],
  "comment": "≤ 800 символів",
  "ts": "ISO час відмітки"
}
```
Тривалість: `lt60` = «до 60 хв», `60-70` = «60–70 хв», `gt70` = «понад 70 хв».

### Англійська (`eng`)
```json
{
  "s": "done | miss",
  "bonus": false,
  "topic": "≤ 150 символів",
  "hw": { "text": "≤ 400 символів", "done": true | false | null },
  "energy": 1-5 | null,
  "reasons": [...],
  "comment": "≤ 800 символів",
  "ts": "ISO"
}
```
- `hw` — домашнє завдання від тютора (Preply): що задали + позначка «виконав».
- Поле `topic` — з автопідказками з попередніх тем.

Обов'язковий лише статус. Усе інше — опційне, з кнопкою «Пропустити».
**Чипи причин** (`reasons`) показувати лише при `miss`: Втома · Не було часу · Спина · Хвороба · Інше. Мультивибір.
**Енергія:** 5 емодзі (😫 😕 😐 🙂 🤩).

### Початкова історія (імпортувати під час першого запуску, якщо сховище порожнє)
- 2026-09-25 — тренування, виконано (без деталей)
- 2026-09-28 — тренування, виконано, `dur: lt60`, `back: false`

## 5. Екрани (нижня панель вкладок)

1. **Сьогодні** — сезонна шапка; картка сьогоднішньої звички (назва дня, фокус тренування) → кнопки «Виконав» / «Не виконав» → покрокова форма опційних полів (bottom sheet). Якщо сьогодні вихідний — показати наступну заплановану звичку й дату. Швидка кнопка «+ бонус».
2. **Календар** — сітка місяця Пн–Нд, свайп/стрілки між місяцями.
3. **Аналітика**.
4. **Англійська** — пройдені теми, домашки, матеріал для практики.
5. **Налаштування** — розклад, паузи, контрольні точки, імпорт/експорт, про застосунок.

Використати Telegram `BackButton` для вкладених екранів, `HapticFeedback` (легкий impact при відмітці, success при досягненні), `expand()` при старті.

## 6. Дизайн: сезони і час доби

- **Сезони календарні** (Україна): зима = груд–лют, весна = бер–трав, літо = черв–серп, осінь = вер–лист.
  - 🍂 Осінь: листя, що повільно падає; теплі помаранчево-бурі тони.
  - ❄️ Зима: сніжинки, морозний візерунок по краях.
  - 🌸 Весна: пелюстки, свіжа зелень.
  - ☀️ Літо: сонячні відблиски; ввечері/вночі — світлячки.
- **Шапка:** дата («вівторок, 29 вересня»), живий годинник (HH:MM), привітання за часом доби, назва сезону.
- **Небо за часом доби:** градієнт ранок (5–11) / день (11–17) / вечір (17–22) / ніч (22–5).
- **Кольори звичок сталі в усіх сезонах** (сезон змінює лише фон і декор): тренування — один стабільний колір, англійська — інший, контрастні між собою, читабельні у світлій і темній темі. Пропуск — нейтральний контур + хрестик; дискомфорт у спині — маленька червона крапка.
- Світла/темна тема — за `Telegram.WebApp.colorScheme` (у браузері — `prefers-color-scheme`), обидві мають виглядати гарно.
- Анімації лише CSS, легкі (≤ ~20 частинок), `prefers-reduced-motion` → декор статичний.
- Мобільний-first: ширина 360–430 px, safe areas, великі тап-зони (≥ 44 px). Має виглядати доглянуто, не шаблонно.
- Шрифти: системні або Google Fonts з фолбеком.

## 7. Календар (деталі)
- Кожен день: коло кольору звички. Залите = виконав, контур + хрестик = пропустив, бліде = майбутнє заплановане, пусте = вихідний, штриховка = пауза, рамка = сьогодні, маленька позначка «+» = бонус, червона крапка = спина.
- Легенда під сіткою.
- Тап по дню → bottom sheet з усіма деталями запису; можна редагувати або видалити (заднім числом). Майбутні дні — лише перегляд.
- Під календарем — міні-підсумок місяця (X/Y тренувань, X/Y занять).

## 8. Аналітика
Перемикач періоду: 4 тижні / місяць / 3 місяці / усе.
- % виконання окремо по звичках; поточна і найкраща серія.
- Розподіл тривалості тренувань.
- Після якого Дня (1/2/3) найчастіше дискомфорт у спині.
- Топ причин пропусків (з чипів) + останні коментарі до пропусків.
- Енергія: середня; середня енергія у дні виконання vs дні пропуску.
- **Контрольні точки:** 10 жовтня 2026 — міні-чек; 7–8 листопада 2026 — рев'ю; з відліком днів. Користувач може додавати свої.
- **Місячний підсумок-картка:** сезонна ілюстрація, назва місяця, X/Y по кожній звичці, %, найкраща серія, середня енергія, кількість тем, топ-причина пропусків. Верстка «під скріншот». Доступна за будь-який минулий місяць; поточний — з позначкою «в процесі».
- **Сезонні досягнення** (бейджі, сірі поки не отримані, з прогресом), приклади:
  - «Перший крок» — перше тренування; «Серія 5 / 10 / 25 / 50».
  - «Золота осінь» — вересень–листопад без пропущених тренувань (паузи не рахуються).
  - «Перший сніг» — перше тренування взимку.
  - «Зимовий гарт» — 12 тренувань поспіль взимку.
  - «Весняне пробудження» — повернення до тренувань після паузи.
  - «Без відмовок» — календарний місяць без пропусків обох звичок.
  - «Поліглот» — 25 / 50 / 100 тем англійської.
  - «Домашка — святе» — 10 домашок поспіль виконано.
  При отриманні — невелика святкова анімація + haptic success.

## 9. Англійська: пройдені теми
- **Пройдені теми:** список (тема, дата, домашка, коментар до уроку), пошук, фільтр за місяцем, групування однакових тем (скільки разів проходив).
- **Невиконані домашки** — окремий фільтр.
- **«Матеріал для практики»:** кнопка на вкладці (і банер з 3 днів до кінця місяця до 7 числа наступного). Вибір періоду (місяць за замовчуванням або свій діапазон) → формується простий текст: заголовок з періодом, далі по датах — тема, домашка (+ виконав/ні), коментар до уроку. Без промптів і без оцінок — лише дані.
  Доставка: бот надсилає текст у чат (через Worker, `/send-text`; якщо текст > 4000 символів — розбити на кілька повідомлень або надіслати `.txt`-файлом). Фолбек — «Скопіювати».
  Користувач потім сам вставляє це в чат із Claude для практики. Тести в застосунку **не робимо**.

## 10. Імпорт / експорт
- **Формати експорту:** CSV (UTF-8 з BOM, щоб Excel коректно показав кирилицю), JSON (повна копія включно з налаштуваннями і досягненнями), XLSX (аркуші: Тренування, Англійська).
- **Період:** тиждень / місяць / 6 тижнів / усе / свій діапазон (дата від–до).
- **Доставка:** Mini App генерує файл → `POST` на Worker (`/send-file`, `multipart/form-data`: `initData`, файл) → Worker лише перевіряє `initData` і пересилає файл у `sendDocument` без перекодування (щоб вкладатися в 10 мс CPU безкоштовного плану) → бот надсилає документ у чат → toast «Файл у чаті з ботом ✅». Той самий Worker має ендпоінт `/send-text` (для «Матеріалу для практики»).
- **Фолбек:** якщо Worker недоступний — «Скопіювати» (CSV як tab-separated для вставки в таблиці, або JSON).
- **Імпорт:** вибір файлу (JSON/CSV/XLSX) у Mini App + варіант «вставити з буфера». Перед записом — попередній перегляд: кількість записів, період, конфлікти (ті самі дата+звичка). Режими: «Додати (не перезаписувати)» / «Додати і перезаписати конфлікти» / «Замінити все» (з підтвердженням). Сувора валідація схеми.

## 12. Етапи
- **Етап 1 — ядро:** адаптер сховища (CloudStorage + localStorage), розклад і налаштування (розклад, паузи), «Сьогодні» з усіма полями записів, календар, сезонний дизайн і час доби, початкова історія, CHECKLIST.md для GitHub Pages і BotFather.
- **Етап 2 — аналітика:** аналітика, контрольні точки, місячний підсумок-картка, досягнення, вкладка «Англійська» (теми, домашки, пошук).
- **Етап 3 — дані:** Cloudflare Worker, експорт/імпорт, «Матеріал для практики».

Кожен етап — окремий PR. Наприкінці етапу: коротко описати, що зроблено, що перевірити вручну, і оновити CHECKLIST.md.

## 13. Критерії готовності
- Працює в Telegram на iPhone і в Telegram Desktop на macOS; у звичайному браузері — в режимі localStorage.
- Світла і темна тема, ширина 360–430 px.
- Жодних секретів у репо.
- Жодних помилок у консолі; дані не губляться при швидких повторних тапах (черга записів).
