# Habit Tracker — ТЗ (Telegram Mini App)

Особистий трекер звичок: **тренування** + **англійська**. Мова інтерфейсу — українська.
Реалізація поетапно (див. «Етапи»). Цей файл — джерело правди для всіх сесій; якщо рішення змінюються — онови його.

---

## 1. Архітектура

| Частина | Що це | Де |
|---|---|---|
| Інтерфейс | Статичний сайт, чистий HTML/CSS/JS, **без збірки і без npm** (ES-модулі дозволені, кілька файлів ок) | GitHub Pages (корінь репо або `/docs`) |
| Вхід | Telegram-бот «Habit Tracker», відкриває Mini App (Menu Button / Main Mini App) | @BotFather |
| Дані | `Telegram.WebApp.CloudStorage` (синхронізація між iPhone і Telegram Desktop) | Хмара Telegram |
| Експорт файлів | Cloudflare Worker: приймає файл від Mini App, бот надсилає його користувачу в чат через `sendDocument` | `worker/` у репо, деплой вручну через дашборд Cloudflare |

- SDK: `https://telegram.org/js/telegram-web-app.js`.
- XLSX: SheetJS з cdnjs, **закріплена версія**.
- **Браузерний режим:** якщо відкрито поза Telegram — сховище `localStorage` + банер «Режим браузера, дані лише на цьому пристрої». Потрібно для тестування на Mac. Код доступу до даних — через один адаптер (`storage.js`) з двома реалізаціями.
- Нагадувань **немає** (користувач використовує Google Calendar). GitHub Actions не потрібні.

## 2. Безпека
- Токен бота **ніколи** не потрапляє в репо. Лише секрет `BOT_TOKEN` у Cloudflare Worker.
- Worker перевіряє `initData` від Telegram (HMAC-SHA256 за офіційною схемою валідації Mini Apps), бере `user.id` лише з перевіреного `initData`, відхиляє старі `auth_date` (> 24 год).
- CORS: дозволити лише origin GitHub Pages (змінна `ALLOWED_ORIGIN`).
- Ліміт розміру файлу експорту ~2 МБ.

## 3. Розклад (за замовчуванням, редагується в Налаштуваннях)

| День | Звичка | Деталі |
|---|---|---|
| Пн | Тренування | **День 1** — горизонтальні тяги та стабілізація тазу |
| Вт | Англійська | заняття |
| Ср | Тренування | **День 3** — функціональна стабілізація та комплексні тяги |
| Чт | Англійська | заняття |
| Пт | Тренування | **День 2** — вертикальні вектори та передня поверхня стегна |
| Сб, Нд | вихідні | — |

- **Бонусні дні:** можна відмітити звичку в день поза розкладом (напр. англійська в суботу) — зараховується як бонус, не впливає на % пропусків негативно.
- **Пауза:** періоди (хвороба, поїздка) з датою початку/кінця і міткою. Дні паузи не є пропусками і **не ламають серію**.
- **Пауза має пріоритет над пропуском** у відображенні і статистиці: пропуск (`miss`) у день паузи в календарі показується як пауза (штриховка) і не рахується; сам запис лишається, його видно в шторці дня з позначкою «Не рахується». Виконане (`done`) у день паузи рахується як бонус.
- **Нова пауза перекриває наявні пропуски** → питаємо «Перетворити пропуски на паузу?». «Перетворити» — записи пропусків видаляються; «Залишити» — записи зберігаються, але поки діє пауза, не рахуються.
- Вихідні й дні без запланованої звички серію не ламають.
- **Версії розкладу:** зміна розкладу діє з дня збереження; минулі дні рахуються за розкладом, що діяв тоді (статистика не «зʼїжджає»).
- **Пауза без дати кінця** дозволена (`to: null` — «триває»), кнопка «Я повернувся» завершує її вчорашнім днем.
- **Дата старту** (`startDate`): заплановані дні до неї не вважаються невідміченими/пропущеними. За замовчуванням — найраніша дата початкової історії.

## 4. Модель даних (CloudStorage)

Ліміти CloudStorage: до 1024 ключів на користувача, значення до 4096 символів.

> ⚠️ Ключі CloudStorage допускають лише `A-Z a-z 0-9 _ -` (двокрапка заборонена), тому роздільник — `_`.

- Запис: ключ `e_YYYY-MM-DD_train` або `e_YYYY-MM-DD_eng` → JSON.
- Налаштування: `settings`:
  ```json
  {
    "schemaVersion": 1,
    "startDate": "2026-09-25",
    "schedule": [{ "from": "2000-01-01", "days": [{ "train": 1, "eng": false }, "… 7 днів, 0 = пн"] }],
    "workouts": { "1": "горизонтальні тяги…", "2": "…", "3": "…" },
    "pauses": [{ "id": "p…", "from": "YYYY-MM-DD", "to": "YYYY-MM-DD | null", "label": "≤ 40 символів" }],
    "checkpoints": [{ "id": "…", "date": "YYYY-MM-DD", "to": "YYYY-MM-DD | null", "label": "…" }]
  }
  ```
  `train`: 0 — немає, 1/2/3 — номер Дня програми.
- Досягнення: `ach` (id → дата отримання).
- Близько 5 записів на тиждень → запасу ключів на кілька років. Закласти функцію «упакувати старі місяці» (записи місяця в ключі `m_YYYY-MM_N`, кожен ≤ 4096 символів; окремий ключ `e_…` має пріоритет над пакетом), запускається лише коли ключів > 900.
- Завжди валідувати довжину перед записом; при помилці CloudStorage — показати статус і повторити.
- Статус синхронізації в шапці: «збережено» / «зберігаю…» / «помилка».

### Тренування (`train`)
```json
{
  "s": "done | miss",
  "bonus": false,
  "day": "1 | 2 | 3 | null",
  "dur": "lt60 | 60-70 | gt70 | null",
  "back": true | false | null,
  "energy": 1-5 | null,
  "reasons": ["tired","no_time","back","sick","other"],
  "comment": "≤ 800 символів",
  "ts": "ISO час відмітки"
}
```
Тривалість: `lt60` = «до 60 хв», `60-70` = «60–70 хв», `gt70` = «понад 70 хв».
`day` — День програми: для запланованого тренування береться з розкладу, для бонусного питається у формі (потрібно для аналітики «спина після Дня N»).
`bonus` виводиться автоматично: `true`, якщо звичка не була запланована на цю дату (або дата в паузі).
Поля, що не стосуються статусу, очищуються: для `miss` — `dur`, `back`, `topic`, `hw`; для `done` — `reasons`.

### Англійська (`eng`)
```json
{
  "s": "done | miss",
  "bonus": false,
  "topic": "≤ 150 символів",
  "hw": { "text": "≤ 400 символів", "done": true | false | null },
  "energy": 1-5 | null,
  "reasons": [...],
  "comment": "≤ 800 символів",
  "ts": "ISO"
}
```
- `hw` — домашнє завдання від тютора (Preply): що задали + позначка «виконав».
- Поле `topic` — з автопідказками з попередніх тем.

Обов'язковий лише статус. Усе інше — опційне, з кнопкою «Пропустити».
**Чипи причин** (`reasons`) показувати лише при `miss`: Втома · Не було часу · Спина · Хвороба · Інше. Мультивибір.
**Енергія:** 5 емодзі (😫 😕 😐 🙂 🤩).

### Початкова історія (імпортувати під час першого запуску, якщо сховище порожнє)
- 2026-09-25 — тренування, виконано (без деталей)
- 2026-09-28 — тренування, виконано, `dur: lt60`, `back: false`

## 5. Екрани (нижня панель вкладок)

1. **Сьогодні** — сезонна шапка; картка сьогоднішньої звички (назва дня, фокус тренування) → кнопки «Виконав» / «Не виконав» → покрокова форма опційних полів (bottom sheet). Якщо сьогодні вихідний — показати наступну заплановану звичку й дату. Швидка кнопка «+ бонус».
2. **Календар** — сітка місяця Пн–Нд, свайп/стрілки між місяцями.
3. **Аналітика**.
4. **Англійська** — пройдені теми, домашки, матеріал для практики.
5. **Налаштування** — розклад, паузи, контрольні точки, імпорт/експорт, про застосунок.

Використати Telegram `BackButton` для вкладених екранів, `HapticFeedback` (легкий impact при відмітці, success при досягненні), `expand()` при старті.

## 6. Дизайн: сезони і час доби

- **Сезони календарні** (Україна): зима = груд–лют, весна = бер–трав, літо = черв–серп, осінь = вер–лист.
  - 🍂 Осінь: листя, що повільно падає; теплі помаранчево-бурі тони.
  - ❄️ Зима: сніжинки, морозний візерунок по краях.
  - 🌸 Весна: пелюстки, свіжа зелень.
  - ☀️ Літо: сонячні відблиски; ввечері/вночі — світлячки.
- **Сезонні сцени в шапці «Сьогодні»** (інлайновий SVG, `js/scenes.js`, без зовнішніх картинок):
  - Осінь: гарбузи на пагорбах (увечері/вночі світяться), купки листя, дерево з рудим листям.
  - Зима: сніговик, засніжені ялинки; з 15.12 по 15.01 вночі — гірлянда на ялинках.
  - Весна: квітучі дерева, проліски, пташки й метелики (вдень).
  - Літо: соняшники, хмаринки; ввечері/вночі — світлячки.
  - Сцени реагують на час доби (затемнення, теплий вечір, нічні вогники). Вдень і вранці — без фільтрів (живі кольори), увечері/вночі — лише затемнення без сепії й знебарвлення в сірий. Пагорби непрозорі (не змішуються з небом у сіро-бежевий). Земля має власний насичений колір для сезону × часу доби × теми і плавно переходить у фон сторінки.
  - Декор лише в шапці й на тлі: частинки падають тільки в межах шапки «Сьогодні», ніколи не під картками. `prefers-reduced-motion` → усе статично.
- **Превʼю дизайну:** `?season=autumn|winter|spring|summer&time=morning|day|evening|night&garland=1` або «Налаштування → Про застосунок». Живе лише в памʼяті: параметри одразу прибираються з адреси, вгорі банер «Превʼю … · Вийти»; вихід чи перезапуск повертають реальний сезон і час.
- **Шапка:** дата («вівторок, 29 вересня»), живий годинник (HH:MM), привітання, назва сезону.
- **Привітання** залежить лише від реального місцевого часу (ранок 5–12 «Доброго ранку», день 12–18 «Доброго дня», вечір 18–23 «Доброго вечора», ніч 23–5 «Доброї ночі») і **не залежить від превʼю** та `?time=…`. Літній/зимовий час враховує сама система (`getHours()`). Межі відрізняються від меж неба нижче.
- **Небо за часом доби:** градієнт ранок (5–11) / день (11–17) / вечір (17–22) / ніч (22–5).
- **Сезонні кольори звичок** (`css/palette.css`, CSS-змінні). Кожен сезон має пару тренування / англійська і акцент інтерфейсу (кнопки, прогрес, «Зберегти», активна вкладка, фокус):

  | Сезон | Тренування | Англійська | Акцент |
  |---|---|---|---|
  | Осінь | гарбузовий `#E2620C` / темна `#FF7B1C` | сливовий `#9B3DB8` / `#D57BEA` | золотий `#A16207` / `#FACC15` |
  | Зима | синій `#1976D2` / `#3DA5FF` | журавлинний `#D0213F` / `#FF4F6E` | хвойний `#166534` / `#6EE7A0` |
  | Весна | персиковий `#FF8F63` / `#FF8F5C` | салатовий `#45A21C` / `#74CF3A` | квітковий `#BE185D` / `#F9A8D4` |
  | Літо | зелений `#0F9D58` / `#2FD27A` | жовтий `#FFC107` / `#FFD21F` | небесний `#0369A1` / `#7DD3FC` |

  **Кольори насичені** (OKLCH chroma ≈ 0.13–0.21) і не змішуються з темною базою: жодних `color-mix`, фільтрів чи затемнювальних шарів поверх палітри.
  Контраст (WCAG 2.1) для обох тем: фігура/заливка до картки ≥ 3:1, текст на заливці ≥ 4.5:1 (білий або темний — що контрастніше), кольоровий текст на картці ≥ 4.5:1. Світлим заливкам (персиковий і жовтий у світлій темі) — темніша обвідка, щоб мати ≥ 3:1.
  **«Заплановано»** — напівпрозорий тон + суцільне кільце кольору звички (2 px): фігура чітко читається на картці і в темній темі. Лише тон без кільця виглядає сірим — так робити не можна.
- **Превʼю — єдине джерело істини:** сезон, час доби і гірлянда для плашки, сцени, палітри, частинок і банера читаються з одного стану превʼю в `seasons.js` (`currentLook()`); будь-яка його зміна (посилання, «Про застосунок», «Вийти») сама перемальовує все через `onPreviewChange`. Стан лише в памʼяті: «Вийти» чи перезапуск повертають реальний вигляд.
- **Яка палітра де:** «Сьогодні», аналітика та інші вкладки — палітра поточного сезону (або превʼю). **Календар — палітра сезону місяця, що переглядається** (гру–лют зима, бер–трав весна, чер–сер літо, вер–лис осінь), незалежно від превʼю. Атрибут `data-pal` ставиться на власний контейнер календаря під час рендеру, а фон і декор навколо підлаштовуються слідом. Зміна помітна і в порожньому місяці: сезонна смужка зверху картки, заголовок місяця в акценті, мітка сезону, стрілки, кільця «заплановано», легенда, тонована доріжка «Підсумку місяця». Шторка дня — палітра сезону своєї дати.
- **Не лише колір:** звички розрізняються формою: тренування — коло, англійська — заокруглений квадрат (у календарі, легенді, мітках списків). У картках — різні іконки (гантель / бульбашка).
- Пропуск — нейтральний контур + хрестик; дискомфорт у спині — маленька червона крапка.
- Світла/темна тема — за `Telegram.WebApp.colorScheme` (у браузері — `prefers-color-scheme`), обидві мають виглядати гарно.
- Анімації лише CSS, легкі (≤ ~20 частинок), `prefers-reduced-motion` → декор статичний.
- Мобільний-first: ширина 360–430 px, safe areas, великі тап-зони (≥ 44 px). Має виглядати доглянуто, не шаблонно.
- Шрифти: системні або Google Fonts з фолбеком.

## 7. Календар (деталі)
- Кожен день: фігура кольору звички (коло — тренування, квадрат — англійська). Залите = виконав, контур + хрестик = пропустив, бліде з обвідкою = заплановано, пунктир = не відмічено (минуле), пусте = вихідний, помітна штриховка з обвідкою = пауза, рамка = сьогодні, позначка «+» = бонус, червона крапка = спина.
- **Дві звички в один день:** замість великої фігури — номер дня і дві маленькі мітки (коло + квадрат) зі своїми станами.
- Легенда під сіткою (з формами і «дві звички в один день»).
- Тап по дню → bottom sheet з усіма деталями запису; можна редагувати або видалити (заднім числом). Форма запису чи редактор **відкриваються в тій самій шторці** (вміст замінюється, у шапці «назад», Telegram BackButton повертає до деталей дня). Майбутні дні — лише перегляд.
- Під календарем — міні-підсумок місяця (X/Y тренувань, X/Y занять).

## 8. Аналітика
Перемикач періоду: 4 тижні / місяць / 3 місяці / усе.
- % виконання окремо по звичках; поточна і найкраща серія.
- Розподіл тривалості тренувань.
- Після якого Дня (1/2/3) найчастіше дискомфорт у спині.
- Топ причин пропусків (з чипів) + останні коментарі до пропусків.
- Енергія: середня; середня енергія у дні виконання vs дні пропуску.
- **Контрольні точки:** 10 жовтня 2026 — міні-чек; 7–8 листопада 2026 — рев'ю; з відліком днів. Користувач може додавати свої.

**Правила розрахунку (Етап 2а, `js/analytics.js` — чисті функції):**
- Ті самі правила, що в календарі: заплановане — за версією розкладу на дату; до `startDate` нічого не рахується; **пауза має пріоритет** — пропуск у день паузи не рахується (ні у %, ні в причинах, ні в енергії), виконане в паузу — бонус; пропуск поза планом не рахується.
- **Періоди:** 4 тижні — останні 28 днів включно з сьогодні; місяць — з 1 числа поточного; 3 місяці — з 1 числа позаминулого; усе — з `startDate`. Початок обрізається `startDate`, діапазон дат показується під перемикачем.
- **% виконання** = виконано / (виконано + пропущено + не відмічено в минулому). Сьогоднішнє невідмічене не рахується (день ще триває). Бонуси — окремо, % не псують. Поруч — розбивка: пропущено, не відмічено, бонус.
- **Серії** — за весь час (не залежать від періоду), окремо по звичках: виконання поспіль; бонус продовжує серію; пропуск і невідмічений минулий день обривають; вихідні, паузи й сьогоднішнє невідмічене — ні.
- **Тривалість, спина, енергія** — з виконаних тренувань/занять періоду, включно з бонусами. Спина по Днях — частка тренувань із дискомфортом серед тих, де є відповідь про спину (поле `day`).
- **Чесний порожній стан:** поки даних мало, картки показують, скільки є і скільки треба: тривалість — від 3 відповідей, спина — від 3, середня енергія — від 3 оцінок, порівняння енергії «виконав / пропуск» — від 2 оцінок у кожній групі. Якщо у періоді < 10 відміток — плашка «Даних поки мало». Якщо немає ні відміток, ні запланованого — окремий порожній екран.
- **Графіки:** SVG/CSS без бібліотек, кольори лише з токенів палітри (`--hc*`, `--accent`, `--danger` для спини — як крапка «спина» в календарі). Кільце % має форму звички: коло — тренування, заокруглений квадрат — англійська. Числа й підписи — нейтральним чорнилом.
- **Контрольні точки:** угорі вкладки — найближча точка з відліком; внизу — усі точки. Для кожної — відрізок від попередньої точки (або `startDate`) до дати точки (для майбутньої — до сьогодні) з X/Y по звичках і бонусами. Стани: майбутня (відлік днів), «сьогодні» (у межах `date`…`to`), минула. Власні точки додаються/видаляються в «Налаштування → Контрольні точки» (назва ≤ 60 символів, одна дата або діапазон).
- **Місячний підсумок-картка:** сезонна ілюстрація, назва місяця, X/Y по кожній звичці, %, найкраща серія, середня енергія, кількість тем, топ-причина пропусків. Верстка «під скріншот». Доступна за будь-який минулий місяць; поточний — з позначкою «в процесі».
- **Сезонні досягнення** (бейджі, сірі поки не отримані, з прогресом), приклади:
  - «Перший крок» — перше тренування; «Серія 5 / 10 / 25 / 50».
  - «Золота осінь» — вересень–листопад без пропущених тренувань (паузи не рахуються).
  - «Перший сніг» — перше тренування взимку.
  - «Зимовий гарт» — 12 тренувань поспіль взимку.
  - «Весняне пробудження» — повернення до тренувань після паузи.
  - «Без відмовок» — календарний місяць без пропусків обох звичок.
  - «Поліглот» — 25 / 50 / 100 тем англійської.
  - «Домашка — святе» — 10 домашок поспіль виконано.
  При отриманні — невелика святкова анімація + haptic success.

## 9. Англійська: пройдені теми
- **Пройдені теми:** список (тема, дата, домашка, коментар до уроку), пошук, фільтр за місяцем, групування однакових тем (скільки разів проходив).
- **Невиконані домашки** — окремий фільтр.
- **«Матеріал для практики»:** кнопка на вкладці (і банер з 3 днів до кінця місяця до 7 числа наступного). Вибір періоду (місяць за замовчуванням або свій діапазон) → формується простий текст: заголовок з періодом, далі по датах — тема, домашка (+ виконав/ні), коментар до уроку. Без промптів і без оцінок — лише дані.
  Доставка: бот надсилає текст у чат (через Worker, `/send-text`; якщо текст > 4000 символів — розбити на кілька повідомлень або надіслати `.txt`-файлом). Фолбек — «Скопіювати».
  Користувач потім сам вставляє це в чат із Claude для практики. Тести в застосунку **не робимо**.

## 10. Імпорт / експорт
- **Формати експорту:** CSV (UTF-8 з BOM, щоб Excel коректно показав кирилицю), JSON (повна копія включно з налаштуваннями і досягненнями), XLSX (аркуші: Тренування, Англійська).
- **Період:** тиждень / місяць / 6 тижнів / усе / свій діапазон (дата від–до).
- **Доставка:** Mini App генерує файл → `POST` на Worker (`/send-file`, `multipart/form-data`: `initData`, файл) → Worker лише перевіряє `initData` і пересилає файл у `sendDocument` без перекодування (щоб вкладатися в 10 мс CPU безкоштовного плану) → бот надсилає документ у чат → toast «Файл у чаті з ботом ✅». Той самий Worker має ендпоінт `/send-text` (для «Матеріалу для практики»).
- **Фолбек:** якщо Worker недоступний — «Скопіювати» (CSV як tab-separated для вставки в таблиці, або JSON).
- **Імпорт:** вибір файлу (JSON/CSV/XLSX) у Mini App + варіант «вставити з буфера». Перед записом — попередній перегляд: кількість записів, період, конфлікти (ті самі дата+звичка). Режими: «Додати (не перезаписувати)» / «Додати і перезаписати конфлікти» / «Замінити все» (з підтвердженням). Сувора валідація схеми.
